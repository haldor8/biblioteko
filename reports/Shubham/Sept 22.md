## **Concepts** 

Digital Library – The central system that manages digitized works (books, music, videos, etc.) and provides access to members.

Work – Any digital content managed by the library (e.g., scanned books, music, videos).

Member – A user of the library who can borrow, propose, or share works.

Librarian – A role responsible for moderation, validation, and metadata enrichment of works.

Repository (Git) – The version-controlled storage structure for managing works and documentation.

Metadata – Descriptive information (title, author, category) added to works for organization and retrieval.

Documentation – All project-related records (architecture, UML, naming guide, etc.), ensuring transparency and maintainability.

Scenario – A functional flow such as borrowing a work, moderating, or exporting content.

Diagram (UML / activity / sequence / class / use case) – Visual models that describe system structure, behavior, and processes.

Design Pattern – Proven object-oriented solutions (e.g., Singleton, Observer) applied to recurring design problems.

Software Architecture – The overall structure of the system (e.g., layered, service-oriented, microservices).

Quality Attributes – Characteristics such as performance, security, modularity, scalability, and maintainability that guide architectural choices.

Architectural Views – Different perspectives (logic, process, development, physical) used to describe the system.

## Actions 

Digitize – Converting physical works into digital PDF format for inclusion in the library.

Borrow / Rent – Process by which a member gains temporary access to a digital work.

Distribute – Automatic sharing of royalty-free works to members.

Moderate – Verification, validation, or rejection of works proposed by members.

Recognize – Using AI tools to perform text recognition (OCR) on digitized works.

Export / Download – Providing works in alternate formats (e.g., Markdown).

Classify – Organizing works by category (Books, Music, Videos, etc.).

Develop – Building modular features and system components.

Test – Performing unit, integration, and validation tests.

Document – Recording architecture, design, and implementation choices.

Check Consistency – Ensuring that glossary, UML diagrams, and documentation align.

## Proper Nouns

Python – Programming language required by the client.

Pyramid – Web framework used on the server side.

TAL/METAL – Template language for UI rendering.

SolidJS / Bootstrap – Client-side frameworks for interface development.

Git – Version control system for repository management.

Gemini / Pixtral – AI models used for text recognition.

CultureBroadcast – The association initiating the project.

PlantUML / Mermaid / D2 – Tools for generating project diagrams.

LLM – Large Language Model, relevant for AI-driven tasks.

## Properties

Decentralized – The library is distributed, not relying on a central authority.

Modular – Features must be independent and reusable.

Encrypted – Borrowed works are protected with the member’s key.

Royalty-free – Works with no copyright restrictions.

Copyrighted – Works under rights that require controlled access.

Public Domain – Works free for anyone to access without restriction.

Traceable – AI usage and prompts must be documented and verifiable.

Structured – Documentation and repository must follow an organized format.

Consistent – Naming conventions, documentation, and UML must align.
